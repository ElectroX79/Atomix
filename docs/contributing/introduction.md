# Contributing to Atomix

Thanks for considering contributing to Atomix!

If you want to contribute, you do not need to understand the whole project before starting. You can learn the codebase while contributing.

Before making your first contribution, make sure you can build Atomix and run its tests.

## Contributor Guide

Use the following pages depending on what you need:

* [Getting Started](getting_started.md) — Build Atomix and run the tests.
* [What to Do](what_to_do.md) — Find something to work on.
* [Communication](communication.md) — Ask questions, propose ideas and discuss problems.
* [Development Workflow](development_workflow.md) — Learn how changes are developed and reviewed.
* [Benchmarks](benchmark.md) — Learn how to create and run benchmarks.
* [Architecture Decision Records](architecture_adr.md) — Learn when and how to create an ADR.

You do not need to read every page before contributing. Start with what is relevant to your change.

## Everything is discussable

Nothing in Atomix is above discussion.

If you have a different opinion, explain your reasoning and provide arguments.Good arguments can change decisions, including existing practices and design choices.

Even this page is open to discussion. Literally.
